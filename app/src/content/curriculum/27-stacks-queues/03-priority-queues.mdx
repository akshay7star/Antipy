# Priority Queues: Always Get the Best Next

A **priority queue** is an abstract data structure where each element has a priority and the dequeue operation always returns the highest-priority element — not the oldest (like a queue) or newest (like a stack).

The classic implementation: a **binary heap** — a complete binary tree where every parent is smaller than its children (min-heap).

**Min-Heap Property**: Every node ≤ both its children. The minimum is always at the root — O(1) access.

## The Heap Stored as an Array

A complete binary tree maps perfectly to a flat array (no pointers needed!):

```python
heap = [1, 3, 5, 8, 9, 6, 7]
#idx:   0  1  2  3  4  5  6

# For node at index i:
parent    = (i - 1) // 2
left_child  = 2 * i + 1
right_child = 2 * i + 2

# Node 3 is at index 1:
# parent of 1 = (1-1)//2 = 0  → heap[0] = 1 ✓
# left of 1   = 2*1+1 = 3     → heap[3] = 8 ✓
# right of 1  = 2*1+2 = 4     → heap[4] = 9 ✓
```

## Python's `heapq` Module

Python only implements a **min-heap**. For max-heap, negate the values:

```python
import heapq

# Create a heap
nums = [5, 1, 8, 2, 9, 3]
heapq.heapify(nums)       # In-place, O(n)
print(nums)               # [1, 2, 3, 5, 9, 8] — valid heap

# Push and pop
heapq.heappush(nums, 4)   # O(log n)
minimum = heapq.heappop(nums)   # O(log n), returns 1

# Push and pop simultaneously (more efficient)
result = heapq.heappushpop(nums, 0)   # Push 0, pop min

# Peek at minimum without popping
minimum = nums[0]         # O(1)
```

## The Top-K Pattern

Finding the K largest elements: maintain a **min-heap of size K**. If a new element beats the heap's minimum, replace it.

```python
def top_k_largest(nums, k):
    heap = nums[:k]
    heapq.heapify(heap)              # O(k)

    for num in nums[k:]:
        if num > heap[0]:            # Larger than current minimum of top-k
            heapq.heapreplace(heap, num)  # Pop min, push num — O(log k)

    return heap   # The k largest elements

# Complexity: O(n log k) — far better than O(n log n) sort for k << n
```

## Heap Operations Complexity

| Operation | Time | Space |
|---|---|---|
| heapify(n items) | O(n) | O(1) — in-place |
| heappush | O(log n) | O(1) |
| heappop | O(log n) | O(1) |
| peek min | O(1) | O(1) |
| top-k from n | O(n log k) | O(k) |
| k-way merge | O(n log k) | O(k) |

def top_k_frequent(nums, k):
    counts = Counter(nums)
    # Min-heap on frequency — keep top k
    return heapq.nlargest(k, counts.keys(), key=counts.get)

print("\n=== Merge K Sorted Arrays ===")
def merge_k_sorted(arrays):
    result = []
    min_heap = []
    # Initialize: push first element from each array
    for i, arr in enumerate(arrays):
        if arr:
            heapq.heappush(min_heap, (arr[0], i, 0))

    while min_heap:
        val, arr_idx, elem_idx = heapq.heappop(min_heap)
        result.append(val)
        # Push next element from same array
        if elem_idx + 1 < len(arrays[arr_idx]):
            next_val = arrays[arr_idx][elem_idx + 1]
            heapq.heappush(min_heap, (next_val, arr_idx, elem_idx + 1))

    return result

arrays = [[1, 4, 7], [2, 5, 8], [3, 6, 9]]
print(f"Input: {arrays}")
print(f"Merged: {merge_k_sorted(arrays)}")

## Heap Sort

Heaps enable an in-place O(n log n) sort with O(1) extra space:

```python
def heap_sort(arr):
    n = len(arr)
    # Build max-heap (heapify from bottom)
    for i in range(n // 2 - 1, -1, -1):
        _sift_down(arr, i, n)

    # Extract elements one by one
    for i in range(n - 1, 0, -1):
        arr[0], arr[i] = arr[i], arr[0]   # Move current max to end
        _sift_down(arr, 0, i)              # Restore heap property

def _sift_down(arr, i, n):
    largest = i
    left, right = 2*i+1, 2*i+2
    if left < n and arr[left] > arr[largest]:
        largest = left
    if right < n and arr[right] > arr[largest]:
        largest = right
    if largest != i:
        arr[i], arr[largest] = arr[largest], arr[i]
        _sift_down(arr, largest, n)
```

> **Pro Tip:** When you see "find K largest/smallest," "K most frequent," or "merge K sorted lists" in an interview — heap is the answer. The pattern is always: maintain a size-K heap, O(n log k) total. For k=1, use a simple max/min scan instead.

> **Common Mistake:** Python's `heapq` is a min-heap only. For max-heap behavior, negate values on push: `heapq.heappush(heap, -val)` and negate on pop: `val = -heapq.heappop(heap)`. Easy to forget the negation!
