# Prefix Sums: Answering Range Queries in O(1)

Without prefix sums, answering "what is the sum of elements from index 3 to 7?" requires adding 5 numbers — O(k) per query. With a prefix sum array built in O(n), every range query answers in **O(1)**. This is one of the most powerful preprocessing tricks in competitive programming and system design.

## Building the Prefix Sum Array

The prefix array `P` where `P[i]` = sum of `arr[0..i-1]`:

```python
def build_prefix(arr):
    n = len(arr)
    prefix = [0] * (n + 1)   # P[0] = 0 (empty prefix)
    for i in range(n):
        prefix[i + 1] = prefix[i] + arr[i]
    return prefix

arr    = [3, 1, 4, 1, 5, 9, 2, 6]
#index:   0  1  2  3  4  5  6  7
prefix = [0, 3, 4, 8, 9, 14, 23, 25, 31]
#          ↑
#          P[0]=0, P[1]=3, P[2]=3+1=4, etc.
```

## O(1) Range Sum Query

```python
def range_sum(prefix, left, right):
    # Sum of arr[left..right] inclusive
    return prefix[right + 1] - prefix[left]

arr    = [3, 1, 4, 1, 5, 9, 2, 6]
prefix = build_prefix(arr)

print(range_sum(prefix, 2, 5))  # 4+1+5+9 = 19 — O(1)!
print(range_sum(prefix, 0, 7))  # Entire array sum = 31
print(range_sum(prefix, 0, 0))  # Just arr[0] = 3
```

> **Why it works**: `P[right+1] - P[left]` = (sum of first `right+1` elements) - (sum of first `left` elements) = sum of elements `left..right`. No loop needed!

## Subarray Sum Equals K

A classic interview problem: "How many subarrays have sum equal to k?"

**Brute force**: O(n²) — check every pair (i,j).  
**Prefix sum + hash map**: O(n) — pure genius.

```python
def subarray_sum_equals_k(nums, k):
    count = 0
    prefix_sum = 0
    seen = {0: 1}   # prefix_sum → how many times seen

    for num in nums:
        prefix_sum += num
        # If (prefix_sum - k) was seen, those subarrays sum to k
        count += seen.get(prefix_sum - k, 0)
        seen[prefix_sum] = seen.get(prefix_sum, 0) + 1

    return count

# Why it works:
# sum(i..j) = prefix[j+1] - prefix[i] = k
# → prefix[i] = prefix[j+1] - k
# So we look for (current_prefix - k) in our hash map!
```

## 2D Prefix Sums: Rectangle Queries

For 2D grids (image processing, matrix problems):

```python
def build_2d_prefix(matrix):
    m, n = len(matrix), len(matrix[0])
    prefix = [[0] * (n + 1) for _ in range(m + 1)]

    for i in range(1, m + 1):
        for j in range(1, n + 1):
            prefix[i][j] = (matrix[i-1][j-1]
                           + prefix[i-1][j]
                           + prefix[i][j-1]
                           - prefix[i-1][j-1])  # Subtract double-counted corner
    return prefix

def rect_sum(prefix, r1, c1, r2, c2):
    return (prefix[r2+1][c2+1]
            - prefix[r1][c2+1]
            - prefix[r2+1][c1]
            + prefix[r1][c1])  # Add back the corner subtracted twice
```

## Performance Comparison

| Approach | Build | Query | Total for q queries |
|---|---|---|---|
| Brute force (no prefix) | O(1) | O(n) | O(n×q) |
| Prefix sum | O(n) | O(1) | O(n + q) |

When q is large (thousands of queries), prefix sums are transformative. This is why **database query planners** and **signal processing** systems use them.

> **Pro Tip:** Prefix sums work with any **associative** and **invertible** operation — not just addition. XOR prefix arrays answer "what's the XOR of elements i..j?" in O(1). Same pattern, different operator: `prefix[right+1] XOR prefix[left]`.

> **Common Mistake:** Off-by-one errors. Always define `prefix[0] = 0` and `prefix[i] = sum(arr[0..i-1])`. The range sum is `prefix[right+1] - prefix[left]`, not `prefix[right] - prefix[left-1]` — that boundary confusion causes subtle bugs.
