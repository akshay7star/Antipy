# Flask Routing: Controlling the Flow

<ToolingVisualizer initialMode="venv" />

When a user visits `https://your-app.com/profile/alice`, how does the server know what Python code to run? It uses **Routing**. Routing is the connective tissue between an HTTP request URL and a specific Python function in your backend.

Flask achieves this using decorators, making the mapping elegant and explicit.

## The `@app.route` Decorator

In Flask, you bind a URL path to a Python function (called a "view function") using the `@app.route()` decorator.

```python
from flask import Flask

app = Flask(__name__)

# The root URL of the website
@app.route('/')
def home():
    return "<h1>Welcome to the Homepage!</h1>"

# A specific path
@app.route('/about')
def about():
    return "<h1>About Our Company</h1><p>We build great Python apps.</p>"
```

When Flask receives a request for `/about`, it scans its registered routes, finds the match, executes the `about()` function, and sends the returned string back to the browser as an HTTP response.

## Dynamic URLs (Path Parameters)

Websites rarely have entirely static URLs. Think about Twitter or GitHub—you wouldn't write a separate Python function for every single user's profile!

Instead, you use **variable rules** to capture parts of the URL. You enclose the dynamic part in angle brackets `<variable_name>`. Flask extracts that segment of the URL and passes it as an argument to your view function.

<interactive-code>
from flask import Flask

app = Flask(__name__)

# The <username> part acts as a wildcard
@app.route('/user/<username>')
def show_user_profile(username):
    # If the user visits /user/alice, username="alice"
    return f"Welcome to the profile page of {username.capitalize()}!"

# You can add type converters to strictly enforce data types
@app.route('/post/<int:post_id>')
def show_post(post_id):
    # post_id is guaranteed to be an integer.
    # If a user visits /post/hello, Flask returns a 404 error!
    return f"Viewing blog post #{post_id}"

@app.route('/path/<path:subpath>')
def show_subpath(subpath):
    # The 'path' converter accepts slashes, unlike the default string converter
    return f"Subpath is: {subpath}"
</interactive-code>

### Available Converters
*   `string`: (default) accepts any text without a slash.
*   `int`: accepts positive integers.
*   `float`: accepts positive floating point values.
*   `path`: like string, but also accepts slashes.
*   `uuid`: accepts UUID strings.

## Handling HTTP Methods (GET, POST)

By default, a Flask route only answers to HTTP `GET` requests (fetching page data). If a user submits a form, their browser typically sends a `POST` request. 

If you try to send a POST request to a standard route, Flask will reject it with a **405 Method Not Allowed** error. You must explicitly allow other methods.

<interactive-code>
from flask import Flask, request

app = Flask(__name__)

# Explicitly allow both GET and POST requests
@app.route('/login', methods=['GET', 'POST'])
def login():
    if request.method == 'POST':
        # The user submitted the form
        username = request.form.get('username')
        password = request.form.get('password')
        return f"Attempting to log in {username}..."
    else:
        # The user simply navigated to the page
        return '''
            <form method="POST">
                <input type="text" name="username" placeholder="Username">
                <input type="password" name="password" placeholder="Password">
                <button type="submit">Login</button>
            </form>
        '''
</interactive-code>

## URL Building (`url_for`)

Hardcoding URLs in your application (e.g., `<a href="/about">`) is dangerous. If you ever change the route from `/about` to `/about-us`, you have to manually find and replace every link in your HTML templates.

Instead, professional Flask developers use `url_for()`. This function generates URLs dynamically based on the *name of the view function*.

```python
from flask import Flask, url_for, redirect

app = Flask(__name__)

@app.route('/')
def index():
    pass

@app.route('/login')
def login():
    pass

@app.route('/user/<username>')
def profile(username):
    pass

# Generating URLs programmatically:
with app.test_request_context():
    print(url_for('index'))
    # Output: /
    
    print(url_for('login'))
    # Output: /login
    
    print(url_for('profile', username='John Doe'))
    # Output: /user/John%20Doe
```

If you ever change the `@app.route('/login')` to `/auth/login`, `url_for('login')` will automatically generate the new URL everywhere in your app instantly!
