# Authentication in FastAPI

In Flask and Django, we used **Sessions** (browser cookies) to remember users. This works perfectly when the backend and frontend are tightly coupled (like when returning HTML templates).

However, FastAPI is built for modern APIs. When a mobile app (iOS/Android) or a separate frontend framework (React/Vue) talks to an API, they don't always use cookies well. Instead, modern APIs use **Tokens**.

## JSON Web Tokens (JWT)

When a user logs in with a correct username and password, the server generates a long, cryptographically signed string of text called a **JWT** (JSON Web Token) and hands it back to the user.

```json
// The Token looks like gibberish:
"eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiIxMjM0NTY3ODkwIi...etc"
```

The client (e.g., the React app) saves this token. Every time the client wants to access a protected route (like viewing their profile), they attach this Token to the HTTP Request Headers.

Because the token is cryptographically signed by the server's secret key, the server can instantly verify it's legitimate without even looking at the database!

## Implementing OAuth2 in FastAPI

FastAPI has profound, built-in support for security flows like OAuth2. 

Instead of writing custom decorators, you use FastAPI's **Dependency Injection** system. You declare that a route *depends* on a valid token.

<interactive-code>
from fastapi import FastAPI, Depends, HTTPException, status
from fastapi.security import OAuth2PasswordBearer

app = FastAPI()

# 1. Define the URL where clients send their username/password to GET a token
oauth2_scheme = OAuth2PasswordBearer(tokenUrl="token")

# 2. A simulated database check
def fake_decode_token(token):
    if token == "fake-super-secret-token":
        return {"username": "alice", "role": "admin"}
    return None

# 3. Create a dependency function
async def get_current_user(token: str = Depends(oauth2_scheme)):
    user = fake_decode_token(token)
    if not user:
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="Invalid authentication credentials",
            headers={"WWW-Authenticate": "Bearer"},
        )
    return user

# 4. Protect a route!
# This route mathematically CANNOT execute unless get_current_user succeeds
@app.get("/users/me")
async def read_users_me(current_user: dict = Depends(get_current_user)):
    return current_user
</interactive-code>

### What happens here?
1. The user requests `/users/me`.
2. FastAPI sees `Depends(get_current_user)`. It pauses the route.
3. It looks at `get_current_user`, which depends on `OAuth2PasswordBearer`.
4. FastAPI automatically checks the incoming HTTP request headers for an `Authorization: Bearer <token>`.
5. If the token is missing, FastAPI instantly rejects the request with a `401 Unauthorized`.
6. If the token is present, it passes it to `get_current_user()`.
7. If the token is valid, it passes the user data into the `read_users_me` function!

## The Power of Swagger UI

The coolest part about using FastAPI's built-in `OAuth2PasswordBearer`?

If you navigate to your `/docs` page, FastAPI will automatically generate a **"Authorize"** button at the top right of the screen! 

You can type a username and password directly into the browser documentation, hit Authorize, and FastAPI will automatically fetch the token and attach it to all subsequent test requests you make in the Swagger UI. It's absolute magic for API testing.

## Passwords

Just like Django and Flask, you must never store plain-text passwords. In FastAPI, the standard library to handle password hashing is `passlib`.

```bash
$ pip install passlib[bcrypt]
```

```python
from passlib.context import CryptContext

# Configure the hashing context to use bcrypt
pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto")

def verify_password(plain_password, hashed_password):
    return pwd_context.verify(plain_password, hashed_password)

def get_password_hash(password):
    return pwd_context.hash(password)
```
