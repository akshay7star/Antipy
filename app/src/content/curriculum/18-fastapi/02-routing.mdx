# Routing & Data Validation

FastAPI's routing system is designed around one core philosophy: **Declare the shape of your data using Python type hints, and the framework will handle everything else.**

This means you write significantly less boilerplate code. You don't have to manually check if `user_id` is an integer, or if the user included a `username` in their POST request. FastAPI validates it, converts it, and documents it automatically.

## Path Parameters

Path parameters are dynamic segments of the URL, just like in Flask.

<interactive-code>
from fastapi import FastAPI

app = FastAPI()

# By using type hints, FastAPI knows item_id must be an integer
@app.get("/items/{item_id}")
def read_item(item_id: int):
    return {"item_id": item_id, "type": type(item_id).__name__}
</interactive-code>

If you visit `/items/5`, FastAPI passes the integer `5` to your function.
If you visit `/items/apple`, FastAPI intercepts the request and instantly returns a standard HTTP 422 (Unprocessable Entity) JSON error explaining that "apple" is not a valid integer.

## Query Parameters

If a function parameter is **not** part of the path (the `{...}` section), FastAPI automatically assumes it is a "query" parameter. 

Query parameters appear at the end of the URL after a question mark: `?skip=0&limit=10`.

```python
from fastapi import FastAPI

app = FastAPI()

# 'skip' and 'limit' are not in the path string!
@app.get("/items/")
def read_items(skip: int = 0, limit: int = 10):
    return {"reading_from": skip, "amount": limit}
```

Because we provided default values (`= 0` and `= 10`), these query parameters are **optional**. If a user simply visits `/items/`, it works perfectly.

If we omit the default value, the parameter becomes **required**.
```python
# The user MUST provide ?search_query=something
@app.get("/search/")
def search_database(search_query: str):
    return {"results_for": search_query}
```

## Request Bodies (POST data)

When a client sends data (like a signup form or a JSON payload), it is sent in the **Request Body**.

To declare a request body, you import `BaseModel` from `Pydantic` and create a data model.

<interactive-code>
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

# 1. Define the exact shape of the expected JSON
class User(BaseModel):
    username: str
    password: str
    age: int | None = None # Optional field
    is_active: bool = True # Optional field with a default

# 2. Use it in your route!
@app.post("/users/")
def create_user(user: User):
    # 'user' is a fully validated Python object, NOT a raw dictionary!
    # Your IDE will autocomplete user.username!
    return {
        "status": "success",
        "saved_username": user.username,
        "is_active": user.is_active
    }
</interactive-code>

When a POST request arrives at `/users/`, FastAPI will:
1. Read the body as JSON.
2. Convert the corresponding types (if a user sends `"age": "25"` as a string, FastAPI smartly converts it to the integer `25`).
3. Validate the data. If `username` is missing, it returns an error detailing exactly what field was missing.
4. Give you the data as a Python object.

## Combining Everything

You can combine Path Parameters, Query Parameters, and Request Bodies all in one single function! FastAPI is smart enough to figure out where each piece of data comes from based on its signature.

```python
@app.put("/items/{item_id}")
def update_item(item_id: int, item: Item, q: str | None = None):
    # item_id comes from the URL path
    # item comes from the JSON body
    # q comes from the URL query string (?q=search)
    return {"item_id": item_id, "item": item, "q": q}
```
