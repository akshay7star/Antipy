# Table Relationships

A relational database is built on the concept of **Relationships**. If you are building an e-commerce store, you don't store a user's entire purchase history inside a single `User` row. You store the user in the `Users` table, the orders in the `Orders` table, and you link them together.

Understanding how to mathematically link data is the most important skill in database design. There are three types of relationships: **One-to-One**, **One-to-Many**, and **Many-to-Many**.

## Foreign Keys

The mechanism that links two tables together is called a **Foreign Key**. 

A Foreign Key is simply a column in Table B that contains the exact Primary Key (`id`) of a row in Table A.

<interactive-code>
import sqlite3

# 1. Create the Parent Table
parent_sql = """
CREATE TABLE users (
    id INTEGER PRIMARY KEY,
    name TEXT NOT NULL
);
"""

# 2. Create the Child Table WITH A FOREIGN KEY
child_sql = """
CREATE TABLE posts (
    id INTEGER PRIMARY KEY,
    title TEXT NOT NULL,
    user_id INTEGER,  -- The Foreign Key column
    
    -- This enforces mathematically that user_id MUST exist in the users table!
    FOREIGN KEY(user_id) REFERENCES users(id)
);
"""
</interactive-code>

## One-to-Many Relationships

The **One-to-Many** relationship is the most common relationship in all of software engineering. 
*   One `User` can write Many `Posts`.
*   One `Customer` can place Many `Orders`.
*   One `Company` can have Many `Employees`.

To implement a One-to-Many relationship, you put the Foreign Key on the "Many" side. (The `Post` gets the `user_id`).

### ORM Implementation (SQLAlchemy)

<interactive-code>
from sqlalchemy import Column, Integer, String, ForeignKey
from sqlalchemy.orm import relationship, declarative_base

Base = declarative_base()

class User(Base):
    __tablename__ = 'users'
    id = Column(Integer, primary_key=True)
    name = Column(String)
    
    # The 'relationship' tells the ORM how to fetch the posts.
    # It does not create a physical column in the 'users' table!
    posts = relationship("Post", back_populates="author")

class Post(Base):
    __tablename__ = 'posts'
    id = Column(Integer, primary_key=True)
    title = Column(String)
    
    # The ACTUAL physical Foreign Key column in the database
    user_id = Column(Integer, ForeignKey('users.id'))
    
    author = relationship("User", back_populates="posts")
</interactive-code>

With this setup, the ORM allows you to do magic like: `my_user.posts` to instantly fetch all posts belonging to that user!

## Many-to-Many Relationships

What if the relationship goes both ways?
*   One `Student` can enroll in Many `Classes`.
*   One `Class` can contain Many `Students`.

You cannot put a Foreign Key on the `Student` (because they have multiple classes), and you cannot put it on the `Class` (because it has multiple students).

To solve a **Many-to-Many** relationship, you must create a third, hidden table called an **Association Table** (or Junction Table).

### The Association Table

This hidden table only has two columns: `student_id` and `class_id`. It acts as a ledger recording every single enrollment.

<interactive-code>
from sqlalchemy import Table

# The Association Table (No Primary Key, just two Foreign Keys)
enrollments = Table(
    'enrollments',
    Base.metadata,
    Column('student_id', ForeignKey('students.id'), primary_key=True),
    Column('class_id', ForeignKey('classes.id'), primary_key=True)
)

class Student(Base):
    __tablename__ = 'students'
    id = Column(Integer, primary_key=True)
    name = Column(String)
    
    # The 'secondary' argument points to the Association Table!
    classes = relationship("Class", secondary=enrollments, back_populates="students")

class Class(Base):
    __tablename__ = 'classes'
    id = Column(Integer, primary_key=True)
    title = Column(String)
    
    students = relationship("Student", secondary=enrollments, back_populates="classes")
</interactive-code>

Now you can write `student.classes.append(physics_class)`, and the ORM will automatically insert a new row into the `enrollments` junction table behind the scenes!

## One-to-One Relationships

A **One-to-One** relationship is relatively rare. 
*   One `User` has exactly One `Profile`.

It is implemented exactly like a One-to-Many relationship (with a Foreign Key on the Profile), but you enforce a `UNIQUE` constraint on the Foreign Key so that no two Profiles can point to the same User. In SQLAlchemy, you use `uselist=False` on the relationship to tell the ORM to return a single object instead of a list.
