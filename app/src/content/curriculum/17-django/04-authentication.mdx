# Authentication in Django

If you've built authentication in Flask, you know it involves manually installing libraries, configuring secret keys, hashing passwords with Werkzeug, and writing custom session management logic.

In Django, authentication is **built-in** and instantly available the second you run `startproject`.

## The Built-in User Model

Django includes a robust `User` model by default. It handles password hashing, email validation, active/inactive statuses, and even granular permissions out of the box.

```python
# To interact with users in your Python code, just import the model!
from django.contrib.auth.models import User

# Creating a new user securely
user = User.objects.create_user(
    username='alice',
    email='alice@example.com',
    password='super_secret_password' # This is automatically hashed!
)

# Checking a password
is_correct = user.check_password('super_secret_password') # Returns True
```

## Logging In and Out

Django provides built-in functions to handle the complex session-cookie logic for you.

<interactive-code>
from django.contrib.auth import authenticate, login, logout
from django.http import HttpResponse

def login_view(request):
    # authenticate() checks the database. 
    # Returns the User object if valid, or None if invalid.
    user = authenticate(request, username='alice', password='super_secret_password')
    
    if user is not None:
        # login() attaches the user to the current session cookie
        login(request, user)
        return HttpResponse("Successfully logged in!")
    else:
        return HttpResponse("Invalid credentials.")

def logout_view(request):
    # logout() destroys the session cookie
    logout(request)
    return HttpResponse("You have been logged out.")
</interactive-code>

## Protecting Views

What if you have a dashboard that only logged-in users should see? Just like Flask, Django provides a simple decorator.

```python
from django.contrib.auth.decorators import login_required
from django.http import HttpResponse

@login_required(login_url='/login/')
def secret_dashboard(request):
    # This code will NEVER execute unless the user is fully logged in
    return HttpResponse(f"Welcome to the vault, {request.user.username}!")
```

If an anonymous (not logged-in) user tries to visit the dashboard, Django automatically intercepts the request and redirects them to `/login/`.

## Authentication in Templates

Because Django's template engine is deeply integrated with the framework, you can check a user's authentication status directly inside your HTML.

The `request` object (and therefore the `user`) is automatically passed to every template by default.

<interactive-code>
<!-- Inside your base.html navbar -->
<nav>
    <a href="/">Home</a>
    
    {% if user.is_authenticated %}
        <p>Welcome back, {{ user.username }}!</p>
        <a href="/dashboard">Dashboard</a>
        <a href="/logout">Logout</a>
    {% else %}
        <p>Welcome, Guest!</p>
        <a href="/login">Login</a>
        <a href="/signup">Sign Up</a>
    {% endif %}
</nav>
</interactive-code>

## Built-in Auth Views

Django goes a step further. It actually includes entirely pre-written Views for Logging in, Logging out, Password Resets, and Password Changes.

You don't even have to write the Python logic for a login page! You just map a URL directly to Django's built-in `LoginView`, provide an HTML template named `login.html`, and Django handles the rest.

```python
# urls.py
from django.urls import path
from django.contrib.auth import views as auth_views

urlpatterns = [
    # Uses Django's pre-written Login logic!
    path('login/', auth_views.LoginView.as_view(template_name='login.html'), name='login'),
    path('logout/', auth_views.LogoutView.as_view(), name='logout'),
]
```
