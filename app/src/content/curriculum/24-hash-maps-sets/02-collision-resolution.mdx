A **collision** occurs when two different keys hash to the same bucket index. It's not a bug — it's mathematically inevitable. With n keys and m buckets, once n > m (and even before due to the **birthday paradox**), collisions happen. The hash table's secret is how it handles them gracefully.

## Strategy 1: Separate Chaining

Each bucket holds a **linked list** (or Python list) of all key-value pairs that hash to it. On collision, simply append to the chain.

```python
class ChainingHashMap:
    def __init__(self, capacity=8):
        self.capacity = capacity
        self.buckets = [[] for _ in range(capacity)]   # List of lists

    def _bucket(self, key):
        return hash(key) % self.capacity

    def put(self, key, value):
        b = self._bucket(key)
        for i, (k, v) in enumerate(self.buckets[b]):
            if k == key:
                self.buckets[b][i] = (key, value)  # Update
                return
        self.buckets[b].append((key, value))         # Insert

    def get(self, key):
        b = self._bucket(key)
        for k, v in self.buckets[b]:
            if k == key:
                return v
        raise KeyError(key)
```

**Chaining Analysis:**
- Average case: O(1) insert, get, delete (chain length = load factor α = n/m)
- Worst case: O(n) — every key in one chain (catastrophic hash function)
- Space: O(n + m) — chains + empty buckets

## Strategy 2: Open Addressing (Linear Probing)

No linked lists. All data lives inside the array. On collision, **probe** to the next available slot.

```python
class LinearProbingHashMap:
    def __init__(self, capacity=8):
        self.capacity = capacity
        self.slots = [None] * capacity
        self.size = 0
        self.DELETED = object()   # Sentinel for deleted slots

    def _probe(self, key):
        idx = hash(key) % self.capacity
        while self.slots[idx] is not None:
            if self.slots[idx] is not self.DELETED and self.slots[idx][0] == key:
                return idx   # Found
            idx = (idx + 1) % self.capacity   # Linear probe: +1
        return idx   # Empty slot

    def put(self, key, value):
        if self.size / self.capacity > 0.7:
            self._resize()
        idx = self._probe(key)
        if self.slots[idx] is None or self.slots[idx] is self.DELETED:
            self.size += 1
        self.slots[idx] = (key, value)
```

## The Load Factor: The Critical Parameter

```python
load_factor = n / m   # n = keys stored, m = total buckets

# Python dict resizes when load factor > 2/3 (≈ 0.67)
# Java HashMap resizes at load factor > 0.75

# Low load factor (0.1) → Fast lookups, wastes memory
# High load factor (0.9) → Memory efficient, slow lookups (long probe chains)
```

**Clustering Problem**: Linear probing creates "clusters" — long consecutive runs of filled slots. Inserting into a cluster extends it, making future insertions even slower. This is **primary clustering**.

**Quadratic Probing** (`(idx + i²) % m`) and **Double Hashing** (`(idx + i*hash2(key)) % m`) reduce clustering at the cost of complexity.

class HashMapChaining:
    def __init__(self, capacity=7):
        self.capacity = capacity
        self.buckets = [[] for _ in range(capacity)]
        self.size = 0

    def put(self, key, value):
        b = hash(key) % self.capacity
        for i, (k, v) in enumerate(self.buckets[b]):
            if k == key:
                self.buckets[b][i] = (key, value)
                return
        self.buckets[b].append((key, value))
        self.size += 1

    def get(self, key, default=None):
        b = hash(key) % self.capacity
        for k, v in self.buckets[b]:
            if k == key:
                return v
        return default

    def stats(self):
        chain_lengths = [len(b) for b in self.buckets]
        occupied = sum(1 for b in self.buckets if b)
        print(f"  Capacity: {self.capacity} | Keys: {self.size} | Load: {self.size/self.capacity:.2f}")
        print(f"  Occupied buckets: {occupied}")
        print(f"  Chain lengths: {chain_lengths}")
        print(f"  Max chain length: {max(chain_lengths)} (worst-case lookup: O({max(chain_lengths)}))")

words = ["alpha", "beta", "gamma", "delta", "epsilon", "zeta", "eta", "theta"]

## Python's dict: Real-World Choices

Python's `dict` uses **open addressing with compact tables** (since Python 3.6). Key design choices:
- **Hash randomization**: Seeds hash with a random value per interpreter run (security)
- **Resize threshold**: 2/3 load factor — pre-emptive resizing avoids long probes
- **Deletion**: Uses "dummy" sentinel entries to not break probe chains
- **Compact layout**: Keys and values stored in separate compact arrays for CPU cache efficiency

```python
import sys

# Python dict grows with powers of 2 (roughly)
sizes = []
d = {}
for i in range(100):
    d[i] = i
    sizes.append(sys.getsizeof(d))

# Shows how Python's dict memory grows in steps (doubling)
unique_sizes = sorted(set(sizes))
print(f"Dict memory at: {unique_sizes[:8]} bytes ...")
```

> **Pro Tip:** Never use a mutable object as a dict key — Python uses `hash()` and `__eq__()`. Lists are mutable and unhashable. Use tuples as composite keys: `d[(row, col)] = value`.

> **Common Mistake:** Assuming dict lookups are always O(1). With a deliberately crafted input (hash DoS attack), an attacker can force all keys into one bucket, making every lookup O(n). Python mitigates this with random hash seeds.
