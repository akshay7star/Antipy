# Logging vs Print: Professional Output

When you are first learning to code, `print("User logged in")` is the easiest way to see what your program is doing. But when you build real applications—like a web server running 24/7 or a data pipeline processing millions of rows—`print()` becomes a massive liability.

Why?
1. **No Context:** `print("Failed")` doesn't tell you *when* it failed, *where* in the file it failed, or *how severe* the failure was.
2. **No Persistence:** Print statements output to the terminal. When you close the terminal, those logs are gone forever.
3. **No Filtering:** You can't easily tell the program to "only show me errors, hide the normal status messages."

To solve this, professional Python developers use the built-in `logging` module.

## The 5 Levels of Logging

The `logging` module categorizes every message by severity. This allows you to filter out noise when things are running smoothly, but see granular details when debugging.

1. **DEBUG (10):** Detailed information, typically of interest only when diagnosing problems.
2. **INFO (20):** Confirmation that things are working as expected.
3. **WARNING (30):** An indication that something unexpected happened, but the software is still working (e.g., "Disk space low").
4. **ERROR (40):** A more serious problem. The software has not been able to perform some function.
5. **CRITICAL (50):** A serious error, indicating that the program itself may be unable to continue running.

```python
import logging

# Basic configuration
logging.basicConfig(level=logging.INFO)

logging.debug("This is a debug message (Hidden by default!)")
logging.info("System initialized successfully")
logging.warning("User login attempts exceeded")
logging.error("Database connection failed")
logging.critical("SERVER OVERHEATING. SHUTTING DOWN.")
```

## Configuring the Logger

The real power of `logging` comes from configuring *how* and *where* logs are formatted and saved. 

We can configure the logger to write output directly to a `.log` file, and we can format the message to automatically include the timestamp, the severity level, and the file name.

<interactive-code>
import logging

# Reset logging (useful in interactive environments)
for handler in logging.root.handlers[:]:
    logging.root.removeHandler(handler)

# Configure the logger
logging.basicConfig(
    level=logging.DEBUG,
    # Automatically add format: [TIME] - [LEVEL] - [MESSAGE]
    format="%(asctime)s - %(levelname)s - %(message)s",
    datefmt="%Y-%m-%d %H:%M:%S"
)

def divide_numbers(a, b):
    logging.info(f"Attempting to divide {a} by {b}")
    try:
        result = a / b
        logging.debug(f"Calculation successful: {result}")
        return result
    except ZeroDivisionError:
        # logging.exception automatically includes the full Traceback!
        logging.exception("Failed to divide by zero!")
        return None

print("=== Starting Application ===")
divide_numbers(10, 2)
print("---")
divide_numbers(10, 0)
</interactive-code>

## Rotating Logs

In enterprise systems, log files grow rapidly. If left unchecked, a single `app.log` file could grow to 100GB and crash the server's hard drive!

Python provides handlers like `RotatingFileHandler` which automatically manages this. You can tell it: *"Keep the log file at a maximum of 5MB. When it hits 5MB, rename it to `app.log.1` and start a fresh `app.log`. Keep a maximum of 3 backup files."*

This guarantees your logs will never consume your entire disk space.
