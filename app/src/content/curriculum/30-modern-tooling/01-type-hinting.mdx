# Type Hinting & Static Analysis

Python is historically a **dynamically typed** language. You can declare `score = 50` and immediately redefine it as `score = "Fifty"` on the next line. While this flexibility is great for quick scripts, it becomes a nightmare in large enterprise codebases.

If a function expects an integer but receives a list, the program might crash deep inside its logic, often exactly when a user is trying to make a purchase. **Type Hinting** brings the safety of statically typed languages (like Java or C++) to Python without losing its flexibility.

## 1. Syntax Declarations

Type hints do **nothing** at runtime. They are completely ignored by the Python interpreter during execution. Instead, they serve as machine-readable documentation that standard third-party Static Analyzers (like `mypy`) use to detect bugs *before* the code runs.

```python
# 1. THE NATIVE DYNAMIC BUG
# What does multiply(5, '2') execute?
# -> It returns '22222' (string repetition). This might cause a silent logic bug later.
def multiply(a, b):
    return a * b

# 2. THE MASTER-CLASS STRUCTURAL CONTRACT
# We restrict 'a' and 'b' to Integers, and enforce the Return Value maps to an Integer.
def vector_multiply(a: int, b: int) -> int:
    return a * b
```

<interactive-code>
def dynamic_multiply(a, b):
    return a * b

def static_multiply(a: int, b: int) -> int:
    return a * b

# Python ignores type hints at runtime!
print("Dynamic:", dynamic_multiply(5, '2'))

# Notice how the static_multiply still executes and returns '22222' at runtime.
# To catch this, we must run a static analyzer like 'mypy' on the file before execution.
print("Static (Runtime ignores hints!):", static_multiply(5, '2'))
</interactive-code>

## 2. Advanced `typing` Structures

Standard primitives (`int`, `str`) aren't enough for complex data structures. The `typing` module provides tools to define exactly what your lists, dictionaries, and functions should contain.

*(Note: In Python 3.9+, you can use native types like `list[str]` and `dict[str, bool]` instead of importing `List` and `Dict` from `typing`)*

```python
from typing import List, Dict, Union, Optional, Callable

# 1. COLLECTIONS
# The list MUST contain exactly strings. The dictionary maps strings to booleans.
def process_names(users: List[str]) -> Dict[str, bool]:
    return {identity: True for identity in users}

# 2. UNION (Multiple Valid Types)
# The configuration accepts a numeric 50 or explicitly a string "High".
def set_bandwidth(limit: Union[int, str]) -> None:
    pass

# 3. OPTIONAL (Can be None)
# Equivalent to Union[str, None]
def fetch_user(user_id: int) -> Optional[str]:
    if user_id == 0:
        return None
    return "Admin"

# 4. CALLABLE (Function Pointers)
# Expects a Function that takes two ints and returns a bool.
def execution_wrapper(func: Callable[[int, int], bool]) -> None:
    result = func(10, 20)
    print(f"Algorithm Result: {result}")
```

## 3. The `mypy` Static Analyzer

Because Python ignores Type Hints during runtime, you must explicitly use a static analyzer like `mypy` to verify your code.

`mypy` does not execute your code physically. It parses the Abstract Syntax Tree (AST), tracking every variable's type to verify 100% compliance.

```bash
# Executing the Static Analysis Matrix
$ mypy server.py

# Failure Output:
server.py:14: error: Argument 1 to "vector_multiply" has incompatible type "str"; expected "int"
```

Integrating `mypy` into a CI/CD pipeline ensures that type-related bugs are caught automatically when developers push code.
