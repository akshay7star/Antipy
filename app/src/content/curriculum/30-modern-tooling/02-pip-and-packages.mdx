# Pip & Package Management

Python's standard library is vast, earning it the phrase *"batteries included."* However, the true power of Python lies in its massive open-source ecosystem. Whether you need to scrape a website, build a machine learning model, or run a web server, someone has likely already written the code for it.

These reusable code bundles are called **packages** or **libraries**.

To download and manage these packages, Python provides a built-in tool called `pip` (Pip Installs Packages).

## Installing Packages

You run `pip` directly from your command line or terminal, not inside the Python interpreter.

```bash
# Install the popular 'requests' library
$ pip install requests

# Install a specific version
$ pip install requests==2.28.1

# Install a minimum version
$ pip install "requests>=2.25.0"
```

When you run `pip install`, `pip` reaches out to the **Python Package Index (PyPI)** — the official repository of all public Python packages — downloads the code, and places it in your system's `site-packages` directory.

Once installed, you can immediately `import` the package in your code.

<interactive-code>
# The 'requests' library makes HTTP requests incredibly simple.
# Note: In this browser environment, we simulate external libraries!
import requests

try:
    response = requests.get("https://api.github.com")
    print("Status Code:", response.status_code)
    print("Content Type:", response.headers['content-type'])
except Exception as e:
    print("Error:", e)
</interactive-code>

## Managing Dependencies

As your project grows, you'll rely on dozens of packages. If you share your code with a teammate or deploy it to a server, they need exactly the same packages installed to run your code.

This is solved using a `requirements.txt` file.

### Freezing Requirements

You can tell `pip` to list every package currently installed along with its exact version using the `freeze` command.

```bash
# Output installed packages to a text file
$ pip freeze > requirements.txt
```

A typical `requirements.txt` looks like this:
```text
certifi==2023.7.22
charset-normalizer==3.2.0
idna==3.4
requests==2.31.0
urllib3==2.0.4
```

### Installing from a Requirements File

When your teammate clones your project, they don't need to manually type `pip install` for every package. They can install everything listed in the file with one command:

```bash
# Install all dependencies listed in the file
$ pip install -r requirements.txt
```

## Upgrading and Uninstalling

Packages receive frequent updates for bug fixes and new features.

```bash
# Upgrade a package to the latest version
$ pip install --upgrade requests

# Uninstall a package
$ pip uninstall requests
```

## The Problem with Global Installs

By default, running `pip install` places the package directly into your main Python installation (global environment). 

Imagine you have Project A that relies on `Django==3.0`, and Project B that relies on `Django==4.0`. If you install globally, **you cannot have both versions installed at the same time**. Project B's installation will overwrite Project A's, breaking Project A.

This is the "Dependency Hell" problem, and it is solved using **Virtual Environments**, which we will cover in the next lesson.
