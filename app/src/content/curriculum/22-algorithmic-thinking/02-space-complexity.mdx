# Space Complexity: Memory Is Not Free

<BigOVisualizer />

When a Senior Engineer reviews your code, they ask two questions: **how fast is it?** and **how much memory does it eat?** Big O for time is half the story. Space complexity is the other half.

Every variable you declare, every list you create, every recursive call you make — all of it consumes RAM. On a server processing 10,000 concurrent requests, an algorithm that leaks memory is catastrophically expensive.

## What Counts as Space?

Space complexity measures the **extra memory** your algorithm uses *beyond the input itself*. This is called **auxiliary space**.

```python
# O(1) auxiliary space — no extra data structures
def find_max(nums):
    maximum = nums[0]       # One variable — constant space
    for num in nums:
        if num > maximum:
            maximum = num
    return maximum

# O(n) auxiliary space — creates a full copy
def double_all(nums):
    return [x * 2 for x in nums]  # New list of size n
```

## The Call Stack Is Memory Too

This is where most engineers go wrong. Every function call pushes a **stack frame** onto the call stack, consuming memory. Recursive algorithms have hidden space costs.

```python
# O(n) space — each call adds a frame to the stack
def factorial(n):
    if n == 0:
        return 1
    return n * factorial(n - 1)

# factorial(5) creates 5 stack frames simultaneously:
# factorial(5)
#   factorial(4)
#     factorial(3)
#       factorial(2)
#         factorial(1)
#           factorial(0) ← base case, start unwinding
```

> **Stack Overflow**: Call `factorial(10000)` in Python and it crashes with `RecursionError: maximum recursion depth exceeded`. The call stack has a finite size — typically ~1000 frames in CPython.

## In-Place vs Out-of-Place

**In-place** algorithms modify the input directly, using O(1) auxiliary space. **Out-of-place** algorithms create new data structures.

```python
# OUT-OF-PLACE: O(n) auxiliary space
def merge_sort_out(arr):
    if len(arr) <= 1:
        return arr
    mid = len(arr) // 2
    left = merge_sort_out(arr[:mid])   # Creates new sub-arrays!
    right = merge_sort_out(arr[mid:])  # Memory allocations at every level
    return merge(left, right)

# IN-PLACE: O(1) auxiliary space (ignoring recursion stack)
def bubble_sort_inplace(arr):
    n = len(arr)
    for i in range(n):
        for j in range(n - i - 1):
            if arr[j] > arr[j + 1]:
                arr[j], arr[j + 1] = arr[j + 1], arr[j]  # Swap in-place
    return arr
```

| Algorithm | Time | Space | Trade-off |
|---|---|---|---|
| Bubble Sort | O(n²) | O(1) | Slow but memory-lean |
| Merge Sort | O(n log n) | O(n) | Fast but eats memory |
| Quick Sort | O(n log n) avg | O(log n) stack | Best overall balance |
| Hash Map lookup | O(1) | O(n) to store map | Speed costs memory |

<interactive-code>
import sys

# Demonstrate space usage
def analyze_space():
    # O(1) - constant extra space
    def find_sum(nums):
        total = 0  # One variable
        for n in nums:
            total += n
        return total

    # O(n) - linear extra space
    def collect_evens(nums):
        return [n for n in nums if n % 2 == 0]  # New list

    # O(n) - hash map storage
    def count_frequencies(nums):
        freq = {}  # Up to n entries
        for n in nums:
            freq[n] = freq.get(n, 0) + 1
        return freq

    data = list(range(1000))

    # Python sys.getsizeof gives memory in bytes
    result_sum = find_sum(data)
    result_evens = collect_evens(data)
    freq_map = count_frequencies(data)

    print(f"Input list size:       {sys.getsizeof(data):>8} bytes")
    print(f"find_sum result:        {sys.getsizeof(result_sum):>8} bytes (O(1))")
    print(f"collect_evens result:   {sys.getsizeof(result_evens):>8} bytes (O(n))")
    print(f"count_freq dict:        {sys.getsizeof(freq_map):>8} bytes (O(n))")

analyze_space()

# Recursive space demo
def recursive_depth(n, depth=0):
    if n == 0:
        print(f"  Max recursion depth reached: {depth} frames on the stack")
        return
    recursive_depth(n - 1, depth + 1)

print("\nRecursion stack frames:")
recursive_depth(10)

## Space-Time Trade-offs: The Golden Rule

> **You can almost always trade space for time, and time for space.**

The **classic example**: Linear search is O(n) time, O(1) space. If you pre-build a hash set, lookup becomes O(1) time but costs O(n) space. This pattern — paying memory to buy speed — is everywhere:

- **Caching / Memoization**: Store computed results to avoid recomputing
- **Prefix Sums**: Precompute cumulative sums for O(1) range queries
- **LRU Cache**: Fixed-size memory for O(1) lookup
- **Lookup Tables**: Pre-computed answers to common sub-problems

> **Pro Tip:** When an interviewer asks you to optimize a solution, think about the space-time axis first. If your current solution is fast but uses too much memory, solve it the other way. If it's slow, spend some memory to cache results.

> **Common Mistake:** Forgetting that Python string slicing `s[a:b]` creates a **new string** — it's O(n) space, not O(1). Same with list slicing `arr[:]`. Always think about what Python copies under the hood.
