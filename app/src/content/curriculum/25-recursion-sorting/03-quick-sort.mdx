# Quick Sort: Divide and Conquer with Partitioning

Quick Sort is the most widely used sorting algorithm in practice. It picks a **pivot**, partitions the array around it so smaller elements go left and larger go right, then recursively sorts both sides. No merging step — the pivot lands in its **final sorted position** after each partition.

## The Lomuto Partition

```python
def partition(arr, low, high):
    pivot = arr[high]     # Pivot = last element
    i = low - 1           # Tracks "smaller zone" boundary

    for j in range(low, high):
        if arr[j] <= pivot:
            i += 1
            arr[i], arr[j] = arr[j], arr[i]

    arr[i + 1], arr[high] = arr[high], arr[i + 1]
    return i + 1   # Pivot's final index

def quicksort(arr, low=0, high=None):
    if high is None:
        high = len(arr) - 1
    if low < high:
        pi = partition(arr, low, high)
        quicksort(arr, low, pi - 1)
        quicksort(arr, pi + 1, high)
    return arr
```

## Pivot Selection Strategies

| Strategy | Risk |
|---|---|
| Last element (naive) | O(n²) on sorted input |
| Random pivot | Expected O(n log n), attack-resistant |
| Median of three | Good worst-case avoidance |

```python
import random

def quicksort_random(arr, low=0, high=None):
    if high is None:
        high = len(arr) - 1
    if low < high:
        rand_idx = random.randint(low, high)
        arr[rand_idx], arr[high] = arr[high], arr[rand_idx]
        pi = partition(arr, low, high)
        quicksort_random(arr, low, pi - 1)
        quicksort_random(arr, pi + 1, high)
    return arr
```

## The O(n²) Worst Case

On a sorted array with last-element pivot: each partition produces a sub-array of size (n-1) and 0. Total work becomes n + (n-1) + ... + 1 = O(n²).

def quicksort_random(arr, low=0, high=None):

        pi = partition(arr, low, high)

def time_sort(func, arr):
    a = arr[:]
    t = time.perf_counter()
    func(a)
    return (time.perf_counter() - t) * 1000, a

## Complexity Summary

| Case | Time | Space (stack) |
|---|---|---|
| Best / Average | O(n log n) | O(log n) |
| Worst | O(n²) | O(n) |

> **Pro Tip:** Quick Sort often beats Merge Sort in practice due to superior **cache locality** — it operates in-place without allocating auxiliary arrays that thrash the CPU cache.

> **Common Mistake:** Using last-element pivot on nearly-sorted data. Always use random pivot or median-of-three in production code.
