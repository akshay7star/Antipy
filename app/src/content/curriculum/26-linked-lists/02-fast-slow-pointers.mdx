# Fast & Slow Pointers: Floyd's Tortoise and Hare

The **fast & slow pointer** technique uses two pointers moving at different speeds through a linked list. The slow pointer moves one step; the fast pointer moves two steps. If a cycle exists, they will inevitably meet.

This elegant algorithm — Floyd's Cycle Detection — solves cycle problems in **O(n) time, O(1) space**, without storing visited nodes in a hash set.

## Problem 1: Detect a Cycle

```python
class ListNode:
    def __init__(self, val=0, next=None):
        self.val = val
        self.next = next

def has_cycle(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next           # Move 1 step
        fast = fast.next.next      # Move 2 steps
        if slow is fast:           # They met — cycle detected!
            return True
    return False   # fast hit None — no cycle

# Why they must meet:
# In a cycle of length L, fast gains 1 step on slow per iteration.
# Distance between them decreases by 1 each step → must reach 0.
```

## Problem 2: Find the Cycle Entry Point

After detecting a cycle, reset one pointer to `head`. Move both one step at a time — they meet at the cycle's entry node.

```python
def detect_cycle_entry(head):
    slow = fast = head

    # Phase 1: Detect cycle
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
        if slow is fast:
            break
    else:
        return None   # No cycle

    # Phase 2: Find entry point
    slow = head       # Reset slow to head
    while slow is not fast:
        slow = slow.next
        fast = fast.next   # Both move 1 step now

    return slow   # Cycle entry node
```

## Problem 3: Find the Middle of a Linked List

When fast hits the end, slow is exactly at the middle:

```python
def find_middle(head):
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
    return slow   # Middle node

# For [1,2,3,4,5]: fast hits end after 2 iterations
# slow lands on 3 — the middle
```

## Problem 4: Happy Number

The "happy number" problem reduces to cycle detection: apply a transformation repeatedly, check if it cycles or reaches 1.

```python
def is_happy(n):
    def digit_sum_of_squares(x):
        total = 0
        while x:
            digit = x % 10
            total += digit * digit
            x //= 10
        return total

    slow = n
    fast = digit_sum_of_squares(n)

    while fast != 1 and slow != fast:
        slow = digit_sum_of_squares(slow)
        fast = digit_sum_of_squares(digit_sum_of_squares(fast))

    return fast == 1
```

## Why Floyd's Algorithm Works (The Math)

Let:
- `F` = distance from head to cycle entry
- `C` = cycle length
- `a` = distance from cycle entry to meeting point

When they meet: fast has traveled `F + a + k*C` steps (k full cycles) and slow `F + a` steps. Since fast moves twice as fast: `F + a + k*C = 2(F + a)` → `F = k*C - a`.

This means: after meeting, if slow resets to head and both move at speed 1, they meet again after exactly `F` more steps — at the **cycle entry point**.

> **Pro Tip:** Fast-slow pointer problems share a common signature: "detect if something eventually repeats" or "find the midpoint in one pass." Whenever you see a linked list cycle, repeated transformation, or "split in half" requirement, fast-slow pointers are your first thought.

> **Common Mistake:** Checking `fast == slow` instead of `fast is slow` in Python. For Python object identity (same node), use `is`. Two different nodes with the same value are `==` but not `is` — and the algorithm cares about the same memory address.
