# Reversing Linked Lists: Pointer Surgery

Reversing a linked list is the most frequently tested linked list operation. It tests whether you can manipulate pointers precisely without losing references. Done incorrectly, you sever the chain and lose the entire list.

## Iterative Reversal: The Three-Pointer Dance

The key insight: you need **three pointers** to reverse a link without losing the rest of the list.

```python
def reverse_list(head):
    prev = None
    curr = head

    while curr:
        next_node = curr.next    # 1. Save what comes next
        curr.next = prev         # 2. Reverse the link
        prev = curr              # 3. Advance prev
        curr = next_node         # 4. Advance curr

    return prev   # prev is now the new head
```

**Step-by-step trace** on `[1, 2, 3]`:

```
Initial:  prev=None, curr=1→2→3
Step 1:   save next=2, 1.next=None, prev=1, curr=2
          None ← 1    2→3
Step 2:   save next=3, 2.next=1, prev=2, curr=3
          None ← 1 ← 2    3
Step 3:   save next=None, 3.next=2, prev=3, curr=None
          None ← 1 ← 2 ← 3
Return prev=3 (new head)
```

## Recursive Reversal

```python
def reverse_list_recursive(head):
    # Base case: empty or single node
    if not head or not head.next:
        return head

    # Recurse: reverse everything after head
    new_head = reverse_list_recursive(head.next)

    # Relink: head.next still points to last node of reversed sublist
    head.next.next = head   # That node should point back to head
    head.next = None        # Head is now the tail — point to None

    return new_head   # Return the new head (unchanged throughout recursion)
```

## Reverse a Sub-List (Positions m to n)

```python
def reverse_between(head, m, n):
    dummy = ListNode(0)
    dummy.next = head
    prev = dummy

    # Move prev to node just before position m
    for _ in range(m - 1):
        prev = prev.next

    curr = prev.next   # Start of sub-list to reverse

    # Reverse n-m times (insert curr.next after prev)
    for _ in range(n - m):
        next_node = curr.next
        curr.next = next_node.next
        next_node.next = prev.next
        prev.next = next_node

    return dummy.next
```

print("\n=== Palindrome Check (Fast-Slow + Reverse) ===")
def is_palindrome(head):
    # Find middle
    slow = fast = head
    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next
    # Reverse second half
    second = reverse_iterative(slow)
    check = second
    result = True
    while check:
        if head.val != check.val:
            result = False
            break
        head = head.next
        check = check.next
    return result

## Reversal Patterns in Interviews

| Problem | Technique |
|---|---|
| Reverse entire list | 3-pointer iterative |
| Reverse in groups of k | Reverse k nodes, recurse on rest |
| Reverse sub-list [m,n] | Navigate to m-1, then insert-front pattern |
| Check palindrome | Fast-slow to middle + reverse second half |
| Reorder list (1→n→2→n-1) | Find middle, reverse second half, merge |

> **Pro Tip:** Always use a **dummy node** (sentinel) at the head when the reversal might change the actual head pointer. `dummy.next = head` lets you always return `dummy.next` without tracking whether the head changed.

> **Common Mistake:** Forgetting to save `curr.next` BEFORE redirecting `curr.next`. Once you write `curr.next = prev`, the reference to the rest of the list is gone forever. Save it first: `next_node = curr.next`.
