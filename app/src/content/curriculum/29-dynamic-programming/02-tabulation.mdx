# Tabulation: Bottom-Up Dynamic Programming

Memoization (top-down DP) starts from the large problem and recursively breaks it down, caching results. **Tabulation** (bottom-up DP) does the opposite: start from the smallest sub-problems, build a table of solutions, and combine them up to the final answer.

The result: **no recursion, no stack overflow risk, and often better performance** due to no function call overhead.

## Fibonacci: Top-Down vs Bottom-Up

```python
# TOP-DOWN (memoization) — recursive
from functools import lru_cache

@lru_cache(maxsize=None)
def fib_memo(n):
    if n < 2: return n
    return fib_memo(n-1) + fib_memo(n-2)

# BOTTOM-UP (tabulation) — iterative
def fib_tab(n):
    if n < 2: return n
    dp = [0] * (n + 1)
    dp[1] = 1
    for i in range(2, n + 1):
        dp[i] = dp[i-1] + dp[i-2]
    return dp[n]

# SPACE-OPTIMIZED bottom-up (only need last 2 values)
def fib_optimal(n):
    if n < 2: return n
    a, b = 0, 1
    for _ in range(2, n + 1):
        a, b = b, a + b
    return b
```

## Coin Change: The Classic DP Problem

**Problem**: Given coin denominations and a target amount, find the minimum number of coins to make the amount.

```python
def coin_change(coins, amount):
    # dp[i] = minimum coins needed to make amount i
    dp = [float('inf')] * (amount + 1)
    dp[0] = 0   # Base case: 0 coins to make amount 0

    for amt in range(1, amount + 1):
        for coin in coins:
            if coin <= amt:
                dp[amt] = min(dp[amt], dp[amt - coin] + 1)

    return dp[amount] if dp[amount] != float('inf') else -1

# coins=[1,5,11], amount=15
# dp[0]=0, dp[1]=1, dp[5]=1, dp[10]=2, dp[11]=1, dp[15]=3 (11+3×1? no: 5+5+5=3!)
```

## Longest Common Subsequence (2D DP)

**Problem**: Find the longest common subsequence (not necessarily contiguous) of two strings.

```python
def lcs(text1, text2):
    m, n = len(text1), len(text2)
    # dp[i][j] = LCS length of text1[:i] and text2[:j]
    dp = [[0] * (n + 1) for _ in range(m + 1)]

    for i in range(1, m + 1):
        for j in range(1, n + 1):
            if text1[i-1] == text2[j-1]:
                dp[i][j] = dp[i-1][j-1] + 1    # Characters match
            else:
                dp[i][j] = max(dp[i-1][j], dp[i][j-1])  # Take best

    return dp[m][n]

# text1="ABCBDAB", text2="BDCAB" → LCS=4 ("BCAB" or "BDAB")
```

## The DP Table as a DAG

Every tabulation problem builds a **directed acyclic graph (DAG)** of sub-problems. Each cell depends only on previously computed cells. Filling the table in the right order ensures dependencies are always satisfied.

```python
# 2D DP dependency pattern:
# dp[i][j] depends on dp[i-1][j] (above) and dp[i][j-1] (left)
# So fill row by row, left to right — dependencies always satisfied

for i in range(1, m + 1):      # Row by row
    for j in range(1, n + 1):  # Left to right
        dp[i][j] = dp[i-1][j] + dp[i][j-1]
```

## Identifying Tabulation Opportunities

> **The recurrence is the key**. If you can write the solution as `dp[i] = f(dp[0..i-1])`, tabulation works. The recurrence defines the DAG.

| Problem Type | Recurrence Pattern |
|---|---|
| Fibonacci-style | `dp[i] = dp[i-1] + dp[i-2]` |
| Coin change | `dp[amt] = min(dp[amt-coin]+1)` |
| LCS | `dp[i][j] = dp[i-1][j-1]+1` or `max(dp[i-1][j], dp[i][j-1])` |
| Knapsack | `dp[i][w] = max(dp[i-1][w], dp[i-1][w-wt]+val)` |
| Edit distance | `dp[i][j] = dp[i-1][j-1]` or `min(...)+1` |

> **Pro Tip:** Once you have a working top-down (recursive + memoization) solution, converting to bottom-up is mechanical: identify the base cases, define the table dimensions, determine the fill order (so dependencies are filled first), and translate the recurrence. The code often becomes shorter and faster.

> **Common Mistake:** Wrong fill order. In 2D DP problems, if `dp[i][j]` depends on `dp[i-1][j-1]`, you must fill top-left to bottom-right. Filling in the wrong order uses uninitialized (wrong) values.
